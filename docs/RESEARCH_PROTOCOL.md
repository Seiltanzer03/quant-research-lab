# Протокол baseline v1

Гипотеза: B1 уменьшает whole-candle envelope score относительно B0 при сопоставимом совместном покрытии. Два кандидата зафиксированы в `research.POLICY` и `MODELS`; grid search и подбор по test отсутствуют.

B0: эмпирические excursions вверх/вниз относительно последней известной цены. Предыдущие 1000 размеченных окон; сезонная группа по UTC-часу используется при ≥100 наблюдениях, иначе pooled history. Минимум 100 обучающих окон. B1: те же excursions в единицах прошлой EWMA-волатильности, alpha=0.06, с масштабом, известным в момент решения. Это эмпирические High/Low-модели, не Student-t close-return и не полноценная HAR.

Для nominal coverage c берутся односторонние marginal quantiles `1 − (1−c)/2`. Обе границы затем проверяются **совместно**: Lower ≤ future Low AND future High ≤ Upper. Union bound не даёт гарантии условной финансовой калибровки; показывается наблюдаемое покрытие на test и разрезы.

Фиксированный горизонт — следующий целый UTC-бар M15/H1/H4. Label используется в обучении только когда его end ≤ simulated as_of. Волатильность для целевого окна рассчитана по прошлым закрытым свечам; regime thresholds также определены по прошлому. При gap на границе target без предыдущего непрерывного close не создаётся. Окна одного горизонта не пересекаются; rolling/session горизонты здесь не смешиваются.

Разделение: первые 60% окон — development, следующие 20% — validation, последние 20% — test. На validation/test параметры не меняются; модель продолжает online-подобное обучение на ставших известными прошлых label. Это walk-forward оценка фиксированного алгоритма, не один fit на первых 60%. Меньше 180 labels — INSUFFICIENT_DATA. Малые H1/H4 выборки не объявляются надёжными.

Метрики: joint coverage 50/80/90/95%; mean/median width 90%; mean whole-candle envelope score 90%; сумма marginal pinball losses для excursions на уровне 0.95. Score нормализован к anchor в bps. `width + 2/alpha * (max(lower−actual_low,0) + max(actual_high−upper,0))` — Winkler-like score для оболочки свечи; это не классический scalar-close interval score. Реализованы разрезы по прошлой волатильности, UTC-часу и месяцу. PIT и полноценные close/touch вероятности пока не реализованы.

Сравнение B0/B1 строго парное по timestamps. Bootstrap блоками UTC-дней, 500 повторов, seed 42; минимум 5 блоков для CI. Разность score = B0 − B1, положительная значит меньший score B1. Сопоставимость coverage — разница ≤2 п.п. Минимум 500 test для исследовательской отметки сравнительной пользы. Пять дней не доказывают устойчивость; режимы и месяцы оцениваются отдельно.

**Ограничение OOS:** разбиение зафиксировано в коде, однако история до запуска могла быть известна разработчику. Повторный пересмотр правил после просмотра test превращает этот период в development. Не называй его навсегда нетронутым holdout. Новый набор кандидатов требует новой версии протокола и действительно новых данных.

Run id привязан к snapshot, профилю, горизонту, policy и hash исходного `research.py`. Git SHA и model versions сохраняются. Системный lock фиксирует зависимости. При обновлении любого влияющего модуля подними версию protocol/model; текущий code hash не заменяет Git SHA полного проекта.

Записи содержат actual issued_at/available_at и отдельный historical as_of. `mode=historical_simulation`, `eligible_for_forward_validation=false`; они не становятся live-прогнозами. Журнал защищён триггерами от UPDATE/DELETE. Новый run не переписывает прежние.

Проверенная модель требует реальной forward-истории и отдельного процесса approval. Его в v0.1 нет: все модели остаются DEMO/BACKTEST_ONLY, `approved=false`, `is_trading_qualified=false`. Преимущество score и прибыльная торговля — разные гипотезы. Для trading нужны самостоятельные правила, затраты и OOS исполнение; вероятность диапазона не равна вероятности выигрыша.
